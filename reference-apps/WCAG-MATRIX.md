# Native WCAG 2.2 A/AA applicability and acceptance matrix

This matrix governs the first native reference presentation for the document, passport and biometric SDKs under APP-ARCH-001 A11Y-01/A11Y-02. It enumerates **all 55 current WCAG 2.2 Level A/AA criteria: 31 A and 24 AA**. Criterion **4.1.1 is obsolete and removed from WCAG 2.2** and is deliberately excluded. AAA criteria are outside this matrix; project-specific requirements such as native target minima remain binding independently.

Criterion numbers, titles and levels were checked on 2026-10-17 against the [W3C WCAG 2.2 Recommendation, 12 December 2024](https://www.w3.org/TR/2024/REC-WCAG22-20241212/). Each criterion link below resolves to that normative source. Native interpretations are project acceptance requirements informed by [W3C WCAG2ICT, 11 December 2025](https://www.w3.org/TR/2025/NOTE-wcag2ict-22-20251211/), which is informative guidance for non-web software, rather than an independent conformance standard.

## Scope, ownership and evidence

“All journeys” means home/capability selection and each workflow's idle, ready, capture simulation, processing simulation, recoverable error, retry, interruption/restoration, cancellation and demonstration-only completion, including return home and platform lifecycle transitions. Test both native platforms, light/dark appearance, supported narrow/landscape layouts, English and development expanded/RTL pseudolocales, default and large accessibility text sizes. Pseudolocales are test fixtures, not reviewed released translations.

Owners are accountable roles: **UI** = shared native presentation maintainer; **Design** = JSONC design/compiler maintainer; **Copy** = localization/content maintainer; **Controller** = workflow-contract/controller maintainer; **Host** = reference-app platform maintainer. The **QA/accessibility owner** records acceptance for every row, coordinating with its listed implementation owners. Adopting apps own their composed journeys, custom copy and OS permission flow; shared components cannot supply acceptance on an adopter's behalf.

Each row's evidence is **pending acceptance**. Existing structural source, generator, controller and native build checks are supporting evidence only. They do not establish keyboard, rendered contrast/layout, assistive-technology or physical-device acceptance. A row marked “absent content/behavior” records a specific current scope rationale, not a permanent or blanket exemption: absence must be confirmed against the actual artifact and reassessed when the feature appears.

Store acceptance receipts with exact source revision/dirty state, app artifact/build identity, device/OS, locale/appearance/text settings, state/journey/test ID, method, result and linked screenshots/tree/recording/manual notes, with reviewer and date. No receipt may contain real identity images or personal data. VoiceOver and TalkBack require complete happy, denial, error, retry, cancel and recovery journeys; a native build or source audit cannot replace them. Rows remain pending until the evidence is reviewed. This document makes no release conformance claim.

# Security policy

## Reporting a vulnerability

Please report security vulnerabilities privately. **Do not open a public issue, pull
request or discussion for a vulnerability.**

Send your report by email to **hello@openproofing.org**. If GitHub private
vulnerability reporting is enabled for this repository, you can also use **Report a
vulnerability** on the repository's **Security** tab.

## What to include

To help us understand and reproduce the problem, include as much of the following as
you can:

- the affected component (for example the SDK, package or file path);
- the commit or version you tested;
- the platform, device and operating system version;
- a description of the vulnerability and its impact;
- steps to reproduce it, or a proof of concept;
- any fix or mitigation you suggest;
- whether you have shared the report with anyone else, such as an upstream project;
- how you would like to be credited, if at all.

Do not send real identity documents, photographs, chip data, biometric samples or other
personal data. Use synthetic data to demonstrate the problem.

## What happens next

We acknowledge every report and keep you informed as we investigate it. We will work
with you on the fix and on the timing of any public disclosure, and we ask that you do
not disclose the vulnerability publicly until a fix is available or we have agreed on a
date with you.

## Scope

This policy covers the code in this repository. No versioned releases have been
published, so fixes are made on `main`. If the vulnerability is in a third-party
component included here, please also report it to that project.

# Optional native presentation contracts

This package implements plain Swift/Kotlin presentation state, typed events, prepared actions, a demonstration engine port and deterministic stubs for biometric, document and passport reference journeys. The Swift runtime imports no capability SDK, UI framework, storage, inference or network client; the Android synthetic reference integration consumes the independent biometric primitives. Headless SDKs remain independent of this package.

The governing standard is [APP-ARCH-001](../governance/architecture/APP-ARCH-001.md). The implemented contract and limitations are [presentation-v1](../contracts/presentation-v1.md). All user wording resolves through generated resources from `design-system/`; SwiftUI/UIKit/Compose/Views only render state and forward actions.

Run `swift test --package-path presentation` for pure controller tests, including the shared fixture vectors. Kotlin tests live under `android/src/test/kotlin` and consume the same fixtures using the `kenshiki.repoRoot` system property supplied by the native Android reference project. Both suites exercise delayed engine callbacks, stale/foreign/duplicate completions, cancellation, retry, in-memory interruption/recovery and an unavailable engine.

No camera, MRZ/NFC reader, model, authentication, BFF connection or authorization is provided. Every outcome is explicitly demonstration-only. Source tests and native compilation do not establish installed physical journeys or VoiceOver/TalkBack acceptance.

## Synthetic biometric contract composition

The Android reference host uses `SyntheticBiometricEngine`. It composes the independently tested BiometricSDK pixel/request/observation/fence and numerical APIs through the existing demonstration port. Every biometric stage runs actual byte validation and synthetic numerical comparison. Pixels are exactly `[0, 1, 2]` (RGB8, 1x1, orientation 1); features are `[3,4]` and `[4,-3]`. These are supplied fixtures, not inference outputs. Digest labels identify the exact UTF-8 bytes `kenshiki.synthetic-demo.artifact/1`, `kenshiki.synthetic-demo.preprocessing/1`, and `kenshiki.synthetic-demo.lineage/1`. The latter is a fixture label, not a verified producer transform record. Attempt/capture/artifact IDs stay stable for the engine's in-memory lifetime, operation IDs are unique and repeated workflow tokens are rejected. All rendered outcomes remain demonstration-only.

The Swift presentation package has no biometric dependency. The retired Swift synthetic engine and its two engine-only tests have been removed; the standalone Swift/Kotlin/C++ primitive conformance and adversarial suites remain. The iOS reference app uses the live selfie acquisition route. The unpublished 0.0.0 presentation API deliberately removes the former public Swift `SyntheticBiometricEngine`, its initializer, `resolve`, `cancel`, and `WorkflowEngine` conformance; existing prototype callers migrate to a supplied `WorkflowEngine` or the live acquisition controller. The compiler snapshot records this source compatibility change. The Android reference host's `biometric-contract` integration module compiles the original standalone SDK source directory against the host's AGP 9 built-in Kotlin, with no copied algorithm source and no runtime dependency added to the standalone SDK. Its original AGP 8 build and tests remain independent. Composition dependencies, original source path and technical tokens are guarded. This module has no separate engine tests; core conformance runs in the standalone SDK, while host tests exercise integration.

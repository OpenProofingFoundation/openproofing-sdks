# Face frame selection v1

This contract defines an optional headless selection mechanism. It accepts host-bound per-frame quality and matcher-preparation observations, returns an original candidate identity and exclusions, and makes no identity, liveness, PAD or passport-authentication decision. The host remains responsible for acquisition, capture admission, timing, storage and complete lineage verification.

## Input and ownership

The host envelope names its capture. The selector configuration names the quality artifact, matcher artifact and policy identities. Each candidate names a unique frame identifier and original frame index, its source digest, quality-source digest, matcher-source digest, quality assessment status/face count/native and mapped unified score, and matcher preparation status/aligned digest. All digests are canonical SHA-256 values. Structurally matching identifiers establish consistency of observations, not authenticated sensor origin or producer execution.

The selector takes no reference portrait, embedding, cosine score or identity threshold. It cannot select the frame with the highest passport similarity. Repeated image bytes are allowed across different frame IDs/indices; they do not establish independent evidence. Duplicate frame identifiers or original indices make the request invalid. The engineering maximum is 32 candidate descriptors, independent of any recognition operating point. An empty valid batch returns no selection.

## Eligibility and ordering

An eligible candidate has a successful quality assessment, exactly one quality-detected face, a finite native unified quality score, finite mapped score within 0 through 100, matching source bindings, and successful actual matcher preparation with a valid aligned digest. Failed and unassessed matcher preparation remain explicit exclusions, even if OFIQ detected a face. Missing facts are not imputed.

Two explicit policies are implemented: first eligible in original frame order and highest native unified quality score. Equal native scores choose the earliest original frame index. The submitted array order is not the frame-order authority. Empty eligible pools return no selection without fallback. Every candidate retains its eligibility/exclusion result. These policies are uncalibrated mechanisms; adding this interface does not establish superior recognition utility.

## Shared Apple implementation

The C++20 implementation is dependency-free and exported through a bounded C ABI. The Swift `FaceFrameSelection` interface calls that implementation; it does not duplicate the ranking algorithm. It is compiled in the existing optional `BiometricInference` product on macOS 13.3 and iOS 18 or later. The portable CMake library can consume the selector without ONNX Runtime. Android integration is not qualified by this Apple milestone.

`AuraFaceComparison.preflight` uses the existing ImageIO decode, Vision revision-3 landmarks and portable C++ alignment. It returns a `FaceImagePreflightObservation` containing public source/aligned digests and route/profile facts, plus an immutable private owner of the exact decoded pixels and geometry. It does not load an embedding model. The prepared-selfie comparison overload consumes that owner and verifies the embedded aligned digest against preflight. It does not rerun selfie detection after selection. Existing original-image comparison remains available.

Synchronous native operations cannot be interrupted mid-kernel. Cancellation is checked before and after preparation and before publication; the host also fences operation/session lifecycle. Hosts bound aggregate retained pixels and concurrency in addition to the per-image decoder ceiling. These ownership and resource checks do not establish acquisition freshness or liveness.

## Quality assessment and release boundary

The optional `biometric/quality-apple` package exports the `BiometricQuality` Apple product and supplies a serialized local OFIQ 1.0.3 assessor. Its reviewed native build uses OpenCV 4.5.5 and the same ONNX Runtime 1.22.0 binary as AuraFace. The runtime profile is distinct from the historical Mac ORT 1.17.3 profile; equivalence requires fresh measurements, not a shared version label. The native framework contains no model weights or second ORT runtime. The sidecar consumes the parent SDK’s narrow `BiometricRuntime` product, which re-exports that same binary target. Primitive consumers resolve only the main package and do not need the local quality framework. The separately provisioned, exact-hash profile contains all nine models and the full configuration, notices and metadata. All 28 component codes and finite native/mapped values, overall return code, actual face count and exact RGB raster digest are preserved. Missing or failed measurements remain missing or failed.

The reference phone host opts into a bounded acquisition window: at most eight originally admitted frames over two seconds, separated by at least 200 ms, subject to SDK engineering bounds on dimensions, retained pixels and encoded bytes. Existing capture gates apply separately to every frame. Each candidate keeps its own original admission, depth and motion receipt. The window can end with a partial nonempty pool; cancellation, guide/anchor discontinuity and consent withdrawal erase retained candidates and fence late callbacks. These engineering limits are not recognition operating points.

The app serializes quality assessment and matcher work under one inference lease. It releases the quality sessions before loading the embedding model, performs actual matcher preparation, and invokes the shared selector. Quality/selection failures cannot manufacture a verified selfie checkpoint. The selected original image and its original receipt proceed through protected persistence and review. A private prepared-image owner survives only in memory; comparison binds that owner to the reloaded selected source and consumes those exact prepared pixels without a second selfie detection pass. Persisted lineage records all candidate observations and exclusions. Historical single-frame records remain readable.

The signed application bundle is the immutable iOS model-loading boundary. Source and raster hashes establish consistency, not authenticated sensor origin, training provenance or liveness. Mac hosts must protect their supplied directory; before/after hashing alone cannot defeat malicious concurrent filesystem mutation. Synchronous OFIQ kernels cannot be cancelled midway: publication is fenced and the inference lease remains held until the kernel settles and its native owner closes. Representative-device latency, peak memory, physical acceptance and recognition utility remain separately measured obligations.

The public API addition is additive to the unpublished 0.0.0 development package. Compiler-derived macOS/iOS API snapshots, exact source locks, adversarial guards, C++ sanitizer tests, Swift wrapper/preflight tests and saved-input integration receipts accompany the change. A passing build does not establish installed capture behavior, recognition gain, PAD or production deployment readiness.
